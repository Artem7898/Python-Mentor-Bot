## Возможности бота

Откройте личный чат с ботом и отправьте `/start`. **Dashboard** — меню Telegram с кнопками программы занятий, примеров кода, установки Python, вопросов, прогресса и настроек.

Откройте выбор языка в Dashboard или используйте `/language`. Бот сохраняет выбор русского, английского или испанского для каждого аккаунта, в том числе после перезапуска. До первого выбора он использует один из поддерживаемых языков Telegram, по умолчанию русский. Прогресс общий для всех языков.

| Команда | Действие |
| --- | --- |
| `/start` | Открыть Dashboard. |
| `/help` | Показать команды и подсказки. |
| `/language` | Выбрать язык бота. |
| `/cancel` | Завершить диалог ввода вопроса. |
| `/questions` | Посмотреть свои вопросы и ответы в личном чате. |
| `/privacy` | Узнать, какие данные хранятся, и запросить удаление в личном чате. |
| `/run (2 + 3) ** 2` | Вычислить выражение и вернуть `25`. |

Вычислитель поддерживает целые и конечные вещественные числа с операциями `+ - * / // % **`. Он ограничивает длину ввода, размер и глубину дерева, показатели степеней и диапазон чисел. Грамматика исключает имена, вызовы, атрибуты, импорты и инструкции.

### Конфиденциальность и вопросы

В группах доступен просмотр каталога уроков. Профиль, сохранённый прогресс, настройки, вопросы и удаление данных доступны в личном чате. Бот связывает профиль с идентификатором аккаунта Telegram и сохраняет имя пользователя, язык, учебную активность и отправленные вопросы.

У одного ученика может быть до пяти открытых вопросов. Исключайте из вопросов токены и персональные данные. Открытыми считаются новые вопросы и вопросы на рассмотрении. Наставник может взять вопрос на рассмотрение и сохранить ответ в закрытой панели. В `/questions` можно прочитать ответ или удалить отдельный вопрос после подтверждения. При запуске и затем каждый час бот удаляет вопросы старше 90 дней, включая вопросы с ответом.

Чтобы удалить профиль, прогресс, закладки, отметки о завершении и вопросы из базы бота, выполните `/privacy` в личном чате и подтвердите удаление. Историей переписки управляйте в Telegram. Срок хранения резервных копий задаёт оператор.

## Установка и запуск

Понадобятся Python 3.14 или новее, SQLite 3.35 или новее и токен Telegram-бота. Для разработки создайте отдельного тестового бота. [@BotFather](https://t.me/BotFather)

В Linux или macOS выполните из корня репозитория.

```bash
python3.14 -m venv python-mentor-bot/.venv
python-mentor-bot/.venv/bin/python -m pip install --require-hashes -r python-mentor-bot/requirements.lock
python-mentor-bot/.venv/bin/python -c 'import sqlite3; print(sqlite3.sqlite_version)'
```

В Windows используйте PowerShell. Выполните команды из корня репозитория.

```powershell
py -3.14 -m venv .\python-mentor-bot\.venv
.\python-mentor-bot\.venv\Scripts\python.exe -m pip install --require-hashes -r .\python-mentor-bot\requirements.lock
.\python-mentor-bot\.venv\Scripts\python.exe -c "import sqlite3; print(sqlite3.sqlite_version)"
```

Задайте `BOT_TOKEN` в окружении процесса или в приватном файле `python-mentor-bot/.env`. Подставьте свой тестовый токен и храните его вне Git и логов.

```dotenv
BOT_TOKEN=replace_with_your_test_bot_token
```

Запускайте бота из каталога приложения. В Bash выполните из корня репозитория.

```bash
(cd python-mentor-bot && .venv/bin/python main.py)
```

В PowerShell выполните из корня репозитория.

```powershell
Push-Location .\python-mentor-bot
.\.venv\Scripts\python.exe main.py
Pop-Location
```

Дождитесь сообщения aiogram `Run polling` и отправьте боту `/start`. Один токен обслуживает один процесс long polling. При конфликте остановите предыдущий экземпляр и проверьте, зарегистрирован ли webhook, прежде чем запускать процесс снова.

### Конфигурация

Переменные процесса имеют приоритет над `.env`. Относительные пути отсчитываются от рабочего каталога приложения.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен BotFather. Неверный формат отклоняется при запуске. |
| `DATABASE_PATH` | Путь к доступной для записи базе SQLite. По умолчанию `data/python_mentor.db`. |
| `BOT_OWNER_IDS` | Необязательный список идентификаторов владельцев в Telegram через запятую. |
| `BOT_MENTOR_IDS` | Необязательный список идентификаторов наставников в Telegram через запятую. |
| `BOT_EDITOR_IDS` | Необязательный список идентификаторов редакторов в Telegram через запятую. |
| `LOG_LEVEL` | Уровень логов приложения. По умолчанию `INFO`. |
| `DEBUG` | Включает отладочное логирование, если `LOG_LEVEL` не задан. |
| `HTTPS_PROXY` | Переменная процесса для прокси к Telegram API, если он требуется. |

Для работы нужен исходящий HTTPS-доступ к `api.telegram.org`. В облачной среде с ограниченной сетью разрешите этот домен и задайте токен в настройках секретов среды. Ошибка соединения с прокси указывает на сетевой путь или настройку прокси. Ошибка аутентификации от Telegram указывает на токен бота. [Telegram Bot API](https://core.telegram.org/bots/api)

### Доступ сотрудников

Указывайте числовые идентификаторы аккаунтов Telegram. Пустой список никому не назначает соответствующую роль. Предоставляйте только нужные роли и перезапускайте процесс бота после изменения конфигурации.

Владельцы и наставники могут открыть `/mentor` в личном чате для просмотра вопросов учеников. Команда `/editor` показывает владельцам и редакторам в личном чате инструкции по работе с учебными материалами. Изменения проходят ревью и проверки CI в Git перед развёртыванием. Сохраняйте идентификаторы уже опубликованных уроков, обновляйте все три перевода и запускайте каждый изменённый пример с указанным интерпретатором и зависимостями.

## Архитектура и хранение данных

Бот работает одним асинхронным процессом с long polling через aiogram. `main.py` отвечает за запуск, HTTP-сессию и жизненный цикл базы. `bot/handlers.py` маршрутизирует команды и нажатия кнопок. `bot/i18n.py` выбирает и отображает язык интерфейса. Каталог уроков предоставляет страницы для обработчиков. Pydantic v2 валидирует конфигурацию и записи. `bot/storage.py` переиспользует соединение aiosqlite и подставляет значения в SQL через параметры.

В SQLite хранятся профили, настройки, прогресс, закладки, отметки о завершении и отправленные вопросы. Временные состояния диалога, например ожидание вопроса, находятся в памяти и истекают. Перезапуск их сбрасывает.

Схема создаётся при запуске. Для переноса старого `python_mentor.db` или `bot_data.db` остановите процессы, которые пишут в базу, и сделайте резервную копию SQLite. В `DATABASE_PATH` укажите доступную для записи рабочую копию. Инициализация добавляет колонки для прогресса или языка в совместимые старые схемы и сохраняет существующие строки. После миграции новые вопросы записываются в `user_questions`.

Копию можно подготовить без токена Telegram. Подставьте абсолютный путь к рабочей копии и выполните из корня репозитория.

```bash
(cd python-mentor-bot && .venv/bin/python create_db.py /absolute/path/to/working.db)
```

Инициализация повторяема. Храните файл `DATABASE_PATH` и резервные копии вне репозитория, в каталоге, доступном учётной записи сервиса и уполномоченным операторам. Используйте обычный файл в каталоге, принадлежащем сервису и закрытом для записи другими аккаунтами. В POSIX-системах используйте права `0700` для каталога и `0600` для базы и резервных копий. В Windows настройте ACL. Применяйте те же ограничения к служебным файлам SQLite. Проверяйте восстановление на закрытой копии и удаляйте резервные копии по истечении срока хранения. [Документация по резервному копированию SQLite](https://sqlite.org/backup.html)

Историческую SQLite-базу убрали из текущей копии репозитория после проверки закрытого локального архива. Файл остался в более ранних коммитах. Историю Git сохранили. Ограничьте доступ к репозиторию и резервным копиям до проверки ранних копий владельцем данных.

## Проверки разработки

Выполните из корня репозитория в Bash.

```bash
python-mentor-bot/.venv/bin/python -m pip install --require-hashes -r python-mentor-bot/requirements-dev.lock
(cd python-mentor-bot && .venv/bin/ruff check .)
(cd python-mentor-bot && .venv/bin/ruff format --check .)
(cd python-mentor-bot && .venv/bin/python -B -m pytest -p no:cacheprovider)
```

В PowerShell перейдите в каталог приложения и используйте `.\.venv\Scripts\python.exe` и `.\.venv\Scripts\ruff.exe` с теми же аргументами pytest и Ruff.

При изменении зависимостей обновите оба файла с хешами через uv из каталога приложения.

```bash
uv pip compile --universal --python-version 3.14 --generate-hashes --no-annotate --output-file requirements.lock requirements.txt
uv pip compile --universal --python-version 3.14 --generate-hashes --no-annotate --constraint requirements.lock --output-file requirements-dev.lock requirements-dev.txt
```

CI запускает Ruff и pytest на Python 3.14 и 3.15, проверяет зависимости бота через pip-audit, сканирует историю Git через Gitleaks с маскированием совпадений и блокирует отслеживаемые базы и dotenv-файлы, кроме файла-примера. Файлы с хешами фиксируют версии зависимостей бота и инструментов разработки. Проверяйте и тестируйте обновления этих файлов вместе с изменениями манифестов.

Автоматические тесты используют имитацию обновлений Telegram и временные базы. Для ручной проверки откройте Dashboard отдельного тестового бота в личном чате. Переключите языки, откройте учебный маршрут, включите компактный режим, добавьте закладку, отметьте урок пройденным и ответьте на короткий тест. После перезапуска проверьте сохранённый прогресс двух аккаунтов. Отправьте вопрос и проверьте права доступа с аккаунтов наставника и ученика. Убедитесь, что в группе можно просматривать каталог, а персональные действия ведут в личный чат. Проверьте удаление тестового профиля через `/privacy`.

При изменении обработчиков или хранилища проверьте устаревшие кнопки, недоступные сообщения, пустые вопросы и одновременные обновления одного аккаунта. При изменении валидации проверьте отсутствие токена, исключение секретов из диагностики, некорректные выражения и числовые пределы. При изменении уроков или переводов проверьте навигацию, экранирование кода и длину сообщений Telegram.
